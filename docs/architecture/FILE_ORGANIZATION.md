# File Organization Guide

## Overview

This document clarifies where TypeScript files should be placed and how they should be organized.

## Directory Purposes

### 1. `workspace/lib/` - Core Library
**Purpose:** Core library code used within the code execution sandbox

**What goes here:**
- Type definitions (`types/*.ts`)
- Core utilities (`errors.ts`, `validator.ts`, `sanitizer.ts`, etc.)
- Configuration (`config.ts`)
- Logging (`logger.ts`)
- Base classes (`tool-wrapper.base.ts`)

**Build output:** Compiles in-place (`.js` alongside `.ts`)

**Used by:** Code execution sandbox, tool wrappers

**Example files:**
```
workspace/lib/
├── types/
│   ├── client.protocol.ts
│   ├── tool.schema.ts
│   ├── tool.wrapper.ts
│   ├── mcp.bridge.ts
│   └── index.ts
├── errors.ts
├── validator.ts
├── sanitizer.ts
├── logger.ts
├── config.ts
└── tool-wrapper.base.ts
```

### 2. `mcp_servers/shared/ts_src/` - Shared Infrastructure
**Purpose:** Infrastructure code used by tool generators and MCP server setup

**What goes here:**
- MCP client for Docker bridge (`mcp-client.ts`)
- Tool generator (`tool-generator.ts`)
- Result cache (`result-cache.ts`)
- PII tokenizer (`pii-tokenizer.ts`)
- Helper functions that need Docker access (`helpers.ts`)

**Build output:** Compiles to `mcp_servers/shared/dist/`

**Used by:** Tool generation scripts, server initialization

**Example files:**
```
mcp_servers/shared/ts_src/
├── mcp-client.ts      # Docker bridge for calling Python MCP servers
├── tool-generator.ts  # Generates TypeScript wrappers from Python tools
├── helpers.ts         # Helper functions for data processing
├── pii-tokenizer.ts   # PII data handling
├── result-cache.ts    # Caching layer
└── index.ts           # Barrel export
```

### 3. `workspace/` root - Main Server
**Purpose:** Main MCP server entry point

**What goes here:**
- `mcp-server.ts` - Main server that Claude Desktop connects to
- `mcp-server.js` - Compiled version (keep in git for easy startup)

**Used by:** Claude Desktop via stdio

### 4. `workspace/servers/` - Generated Tool Wrappers
**Purpose:** Auto-generated tool wrapper code

**What goes here:**
- Generated by `tool-generator.ts`
- One directory per MCP server (database, processing, etc.)
- Auto-generated, don't manually edit

**Example:**
```
workspace/servers/
├── database/
│   ├── index.ts
│   ├── get_sequences.ts
│   └── get_taxonomy.ts
├── processing/
└── alignment/
```

## File Location Decision Tree

```
Is this a TypeScript file?
│
├─ Yes → What does it do?
│  │
│  ├─ Core library (types, validation, errors, logging)
│  │  → workspace/lib/
│  │
│  ├─ Infrastructure (MCP client, tool generator, helpers)
│  │  → mcp_servers/shared/ts_src/
│  │
│  ├─ Main MCP server entry point
│  │  → workspace/mcp-server.ts
│  │
│  └─ Auto-generated tool wrapper
│     → workspace/servers/ (don't create manually)
│
└─ No → Is it Python?
   │
   ├─ Yes → What type?
   │  │
   │  ├─ Base classes (ToolHandler, ServerRegistry)
   │  │  → mcp_servers/shared/py_infra/types/
   │  │
   │  ├─ Utility functions
   │  │  → mcp_servers/shared/py_infra/utils/
   │  │
   │  └─ MCP server tool implementation
   │     → mcp_servers/<server_name>/tools/
   │
   └─ Other file types → See main documentation
```

## Common Scenarios

### Scenario 1: Creating a New Utility Function

**Q:** I want to create a utility function for parsing FASTA files. Where should it go?

**A:** Depends on usage:

- **If used in code execution sandbox** → `workspace/lib/utils.ts` (or similar)
  ```typescript
  // workspace/lib/fasta-parser.ts
  export function parseFasta(content: string) { ... }
  ```

- **If used by tool generator or needs Docker** → `mcp_servers/shared/ts_src/helpers.ts`
  ```typescript
  // mcp_servers/shared/ts_src/helpers.ts
  export async function parseFastaFromContainer(containerId: string) { ... }
  ```

### Scenario 2: Creating a New Type Definition

**Q:** I need to define a new interface for my tool. Where should it go?

**A:** If it's a reusable type → `workspace/lib/types/`

```typescript
// workspace/lib/types/my-types.ts
export interface IMyTool {
  name: string;
  version: string;
}

// Export from index
// workspace/lib/types/index.ts
export * from './my-types.js';
```

### Scenario 3: Creating a New Base Class

**Q:** I want to create a base class for all validation tools. Where should it go?

**A:** Base classes for TypeScript → `workspace/lib/`

```typescript
// workspace/lib/validator.base.ts
export abstract class ValidatorBase {
  abstract validate(input: unknown): boolean;
}
```

### Scenario 4: Creating Infrastructure Code

**Q:** I need to add a new transport layer for MCP communication. Where should it go?

**A:** Infrastructure code → `mcp_servers/shared/ts_src/`

```typescript
// mcp_servers/shared/ts_src/transports/http-transport.ts
export class HTTPTransport implements IMCPTransport {
  // Implementation
}
```

## Build Configuration

### workspace/lib/ Build Config

**File:** `workspace/tsconfig.json`

```json
{
  "extends": "../tsconfig.base.json",
  "compilerOptions": {
    "rootDir": "./lib",
    "outDir": "./lib",  // Compile in-place
    "composite": true
  },
  "include": ["lib/**/*.ts"],
  "exclude": ["servers/**/*"]  // Exclude generated code
}
```

### mcp_servers/shared Build Config

**File:** `mcp_servers/shared/tsconfig.json`

```json
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "rootDir": "./ts_src",
    "outDir": "./dist",  // Compile to dist/
    "composite": true
  },
  "include": ["ts_src/**/*"]
}
```

## Import Patterns

### From workspace/lib/

```typescript
// In code execution sandbox or tool wrappers
import { validator } from '../lib/validator.js';
import type { IToolWrapper } from '../lib/types/index.js';
import { MCPError } from '../lib/errors.js';
```

### From mcp_servers/shared/

```typescript
// In tool generation scripts
import { ToolGenerator } from './mcp_servers/shared/dist/tool-generator.js';
import { MCPClient } from './mcp_servers/shared/dist/mcp-client.js';

// Or using package exports
import { ToolGenerator } from '@mdk-mcp/shared/tool-generator';
```

### Between workspace files

```typescript
// In workspace/lib/config.ts
import { logger } from './logger.js';
import type { IServerConfig } from './types/index.js';
```

## Migration Steps for Existing Files

### If you have duplicate files:

1. **Identify the primary usage**
   - Used in sandbox execution? → `workspace/lib/`
   - Used for infrastructure/tooling? → `mcp_servers/shared/ts_src/`

2. **Check for Docker dependencies**
   - Imports `child_process` or `docker`? → `mcp_servers/shared/ts_src/`
   - Pure utility/logic? → `workspace/lib/`

3. **Move the file**
   ```bash
   # Example: Moving a utility
   mv workspace/some-util.ts workspace/lib/some-util.ts
   
   # Example: Moving infrastructure
   mv workspace/mcp-helper.ts mcp_servers/shared/ts_src/mcp-helper.ts
   ```

4. **Update imports**
   ```bash
   # Find all files that import the moved file
   grep -r "from.*some-util" .
   
   # Update each import path
   ```

5. **Rebuild**
   ```bash
   npm run build
   ```

## Package.json Dependencies

### Root package.json
**Purpose:** Development tools and build scripts

**Contains:**
- TypeScript compiler
- Testing frameworks
- Linters and formatters
- Build orchestration

### mcp_servers/shared/package.json
**Purpose:** Shared infrastructure as a package

**Contains:**
- `@modelcontextprotocol/sdk`
- TypeScript
- Testing tools

**Exports:**
```json
{
  "exports": {
    "./mcp-client": "./dist/mcp-client.js",
    "./tool-generator": "./dist/tool-generator.js",
    "./helpers": "./dist/helpers.js"
  }
}
```

### workspace/package.json (Optional)
If you want to make workspace/lib a package:

```json
{
  "name": "@mdk-mcp/lib",
  "version": "1.0.0",
  "type": "module",
  "main": "./lib/index.js",
  "types": "./lib/index.d.ts",
  "exports": {
    ".": "./lib/index.js",
    "./types": "./lib/types/index.js",
    "./errors": "./lib/errors.js",
    "./validator": "./lib/validator.js"
  }
}
```

## Best Practices

### 1. Don't Duplicate Code
- If code exists in `workspace/lib/`, don't copy to `mcp_servers/shared/`
- Import from the correct location instead

### 2. Use Barrel Exports
```typescript
// workspace/lib/index.ts
export * from './types/index.js';
export * from './errors.js';
export * from './validator.js';

// Then import from index
import { MCPError, validator } from '../lib/index.js';
```

### 3. Keep Build Outputs Separate
- `workspace/lib/*.js` - In-place compilation
- `mcp_servers/shared/dist/*.js` - Separate dist directory
- Never commit `dist/` to git (it's generated)

### 4. Document Dependencies
If `workspace/lib/` needs something from `mcp_servers/shared/`:

```typescript
// ❌ BAD - Creates circular dependency
import { MCPClient } from '../../mcp_servers/shared/dist/mcp-client.js';

// ✅ GOOD - Keep dependencies in correct direction
// mcp_servers/shared can import from workspace/lib
// But not vice versa
```

## Summary

| Location | Purpose | Build Output | Commit JS? |
|----------|---------|--------------|------------|
| `workspace/lib/` | Core library | In-place (lib/*.js) | Optional* |
| `mcp_servers/shared/ts_src/` | Infrastructure | Separate (dist/*.js) | No |
| `workspace/` | Main server | In-place (mcp-server.js) | Yes** |
| `workspace/servers/` | Generated tools | In-place | No*** |

\* Depends on your deployment strategy  
\** For easy startup without build step  
\*** Auto-generated, should be rebuilt
